# GitHub and Hostinger upload guide

This package is the Node.js edition. The existing ChatGPT Sites deployment is unchanged. Uploading source to GitHub does not itself host the application.

## 1. Download and extract

Download StreetCode_NYC_GitHub_Hostinger.zip and extract it. Open the extracted folder. It should contain package.json, package-lock.json, README.md, app, lib, public, scripts, tests, and docs. There are also .gitignore, next.config.ts, and tsconfig.json.

## 2. Upload to the existing GitHub repository

1. Sign into GitHub and open https://github.com/AMV9978/streetcode-nyc.
2. For an empty repository, click “uploading an existing file.” If files are already present, use Add file → Upload files. Review existing work before replacing any files.
3. In Finder, press Command + Shift + Period to show .gitignore.
4. Drag the CONTENTS of the extracted folder into GitHub's upload area. Do not drag the ZIP or the enclosing folder. Preserve the subfolders inside the source.
5. Confirm package.json and package-lock.json are at the repository root, next to app/ and public/.
6. Enter the commit message “Add StreetCode NYC Node.js application” and commit to main for the initial upload.
7. Verify the root file list after committing. Do not upload node_modules, .next, passwords, or personal environment files. None of those are included in this ZIP.

If your GitHub browser upload has trouble with folders, clone the repository in GitHub Desktop, copy the extracted contents into the clone, review changes, commit, and push. Do not enable GitHub Pages: this app needs a Node.js backend.

## 3. Deploy in Hostinger

1. Open hPanel → Websites → Create Website (or Add Website).
2. Choose Web App / Node.js. This is a separate application from angelovasquez.net's WordPress site.
3. Choose Import Git Repository and connect GitHub. Grant access to streetcode-nyc when repository selection is available.
4. Select AMV9978/streetcode-nyc, branch main.
5. Review the settings below. Use the Next.js BACKEND application preset, not a static React/Vite site.

| Field, if shown | Value |
| --- | --- |
| Framework | Next.js |
| Node.js | 24.x (tested with 24.22.1); 22.x must be at least 22.13 |
| Root directory | Repository root, normally ./ |
| Package manager | npm |
| Install command | npm ci |
| Build command | npm run build |
| Start command | npm start |
| Build output directory | .next |
| Secrets / API keys | None required for the included MTA feeds |

The Node process reads PORT when the platform supplies it. Do not hardcode a hosting port. The .next directory is generated by the build; it is not in the ZIP. Some presets manage the start command or output directory automatically. If the screen requires an unfamiliar entry file, stop and review the framework selection instead of guessing server.js.

6. Deploy to Hostinger's temporary URL first.
7. Inspect the build logs and application logs. The build must succeed and the server must start.
8. Test the live application before attaching a domain.

## 4. Acceptance checks

- Open the dashboard, search for Union Sq, choose the L platform group, and switch direction.
- Confirm current feed timestamps and arrivals; a valid empty prediction list is possible at some stations.
- Leave the tab visible for at least 65 seconds and confirm updates continue.
- Pause and resume updates. Confirm returning from a hidden tab resumes refresh.
- Save a station, reload, and confirm it remains saved in that browser.
- Switch between JSON and GTFS-Realtime alert sources; inspect active and planned advisories.
- Open the algorithm lab and try a scenario. It is labeled simulation data.
- Test a phone-sized viewport and keyboard navigation.
- Test API URLs: /api/arrivals?feed=l, /api/alerts?format=json, and /api/alerts?format=protobuf. They should return JSON, not an HTML error page.

A 502 response means an upstream feed failed; inspect logs and retry. A 404 on /api indicates the backend may not have been deployed correctly. Build success alone does not verify outbound MTA access from Hostinger.

## 5. Connect a domain

After acceptance checks, add streetcode-nyc.app if the group owns it, or another chosen domain, in the new app's Hostinger domain settings. Use only the DNS values Hostinger supplies. Wait for DNS and HTTPS verification, then test the custom address. Keep the current working site until the replacement is verified.

## 6. Future changes and group access

Commit future changes to GitHub. Hostinger's GitHub integration supports automatic builds on pushes; confirm your deployment's selected branch and settings. Add group collaborators through GitHub Settings → Collaborators after agreeing on access. Record actual names and contributions in the README before submission.
