THE PROJECT IN SIX PARTS

From a city problem to a graph algorithm.

01

The question

When a corridor slows down or closes, which available route has the lowest cost? The answer changes when a rider prefers fewer transfers.

02

The data model

Stations become vertices. Bidirectional corridor segments become weighted edges. A search state contains both the station and the incoming line so that transfers are counted correctly.

03

The objective

Score = ride minutes + simulated delays + 4 minutes per transfer + preference penalty per transfer. The preference penalty affects ranking, not displayed journey minutes.

04

The algorithm

Dijkstra uses a binary min-heap to expand the cheapest state. Parent links reconstruct the winning path. It is optimal for this model because all transition costs are nonnegative.

05

The boundary

The route lab excludes timetables, train waiting time, direction-specific service, real elevator status, and live arrivals. Step-free filtering applies to every modeled station, even through stations. This is deliberately conservative and simplified.

06

The next iteration

Import official GTFS topology and schedules, add GTFS-RT updates through a backend, model platform access and transfers, then validate against real trips before offering travel advice.
